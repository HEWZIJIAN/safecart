# Internationalization (i18n)

SafeCart is wired for Chrome's native i18n. The **foundation is in place**; translating the UI is incremental and optional.

## What's set up
- `manifest.json` declares **`"default_locale": "en"`** and uses **`__MSG_appName__`** / **`__MSG_appDescription__`** instead of hardcoded English.
- `_locales/en/messages.json` holds the English strings. Chrome serves the user's locale automatically and falls back to `en`.

This is **non-breaking** — for an English user nothing changes; the extension is just now translation-ready.

## Add a language (e.g. Spanish = `es`)
1. Copy `_locales/en/messages.json` → **`_locales/es/messages.json`**.
2. Translate the **`"message"`** values only — never the keys.
   > ⚠️ This is a **scam-warning** tool. A mistranslated warning can mislead or scare users. Have a **native speaker** review the copy — do **not** ship machine translation for the warning strings.
3. Reload the extension (or rebuild + re-zip). Done — Chrome picks the locale.
4. In the Chrome Web Store dashboard you can also add a **localized store listing** per language for better discovery.

Locale codes: `es`, `fr`, `de`, `pt_BR`, `zh_CN`, `ja`, `hi`, etc. (Chrome uses underscores, e.g. `pt_BR`.)

## Localize the in-extension UI (incremental — when you target a market)
Strings in the popup/options/content are still hardcoded English. To translate one:
1. In JS: replace the literal with `chrome.i18n.getMessage("someKey")`.
2. Add `"someKey"` to **every** `_locales/<lang>/messages.json`.

Suggested order of impact:
1. **Popup** (most-seen): tagline, buttons, section labels.
2. **The phishing warning overlay** (`src/content/phishing-overlay.js`) — highest-stakes copy; human-review every language.
3. Onboarding, options, chargeback/breaches pages.

## Priority note
At this stage reach is limited more by **awareness than language**. Stand up the foundation (done), then do real translations once you have traction in a specific market — starting with the store listing + the popup, human-reviewed.
