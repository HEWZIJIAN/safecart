# SafeCart subscription server

Small Node + Express + SQLite + Stripe service that backs the extension's subscription tiers.

The Chrome extension cannot talk to Stripe directly (the secret key would leak, and webhooks need a real HTTPS endpoint). This server is the only piece that holds the Stripe secret and is the source of truth for which `client_reference_id` is on which tier.

## Tiers

| Tier    | Price          | Env var                   |
|---------|----------------|---------------------------|
| Free    | $0             | (not in Stripe)           |
| Premium | $2.49 / month  | `STRIPE_PREMIUM_PRICE_ID` |
| Family  | $4.99 / month  | `STRIPE_FAMILY_PRICE_ID`  |

## Endpoints

| Method | Path                    | Purpose                                                                                  |
|--------|-------------------------|------------------------------------------------------------------------------------------|
| `POST` | `/api/checkout-session` | Creates a Stripe Checkout Session. Auth: `Authorization: Bearer <client_ref-UUID>`.      |
| `POST` | `/api/webhook`          | Stripe webhook target. Raw body. Verifies `Stripe-Signature`.                            |
| `GET`  | `/api/subscription`     | Returns the caller's tier/status. Auth: `Authorization: Bearer <client_ref-UUID>`.       |
| `POST` | `/api/billing-portal`   | Creates a Stripe Billing Portal session so the user can cancel / update payment method.  |
| `GET`  | `/health`               | Liveness probe.                                                                          |

`client_ref` is a UUID generated by the extension on first install and stored in `chrome.storage.sync`. It acts as a bearer token: anyone holding it can read that subscription's tier (no PII) but cannot grant themselves premium without paying.

## Setup (first time)

1. **Install:**
   ```
   cd server
   npm install
   ```

2. **Copy env:**
   ```
   cp .env.example .env
   ```

3. **Add your Stripe secret key** to `.env`:
   ```
   STRIPE_SECRET_KEY=sk_test_...
   ```

4. **Create products + prices in Stripe:**
   ```
   npm run setup:stripe
   ```
   Copy the printed `STRIPE_PREMIUM_PRICE_ID` and `STRIPE_FAMILY_PRICE_ID` into `.env`.

5. **Forward webhooks (dev):**
   ```
   stripe listen --forward-to localhost:3001/api/webhook
   ```
   Copy the `whsec_...` it prints into `.env` as `STRIPE_WEBHOOK_SECRET`.

6. **Run the server:**
   ```
   npm run dev
   ```

## Running end-to-end with the extension

1. Server up on `http://localhost:3001` (the extension defaults to this).
2. Load the extension unpacked (`chrome://extensions` → Load unpacked → repo root).
3. Open the popup → click **Upgrade to Premium** → pick a tier.
4. Stripe Checkout opens in a new tab. Use a test card: `4242 4242 4242 4242`, any future expiry, any CVC.
5. Stripe redirects to `success.html`. The extension polls `/api/subscription` and flips the tier to premium within a few seconds.

## Webhook events handled

- `checkout.session.completed` — first paid session for a `client_ref`. We persist the Stripe customer + subscription ID.
- `customer.subscription.created|updated|deleted` — tier, status, period end, cancel-at-period-end.
- `invoice.payment_failed` — re-syncs the subscription status (Stripe will mark it past_due, etc.).

All events are deduped via `processed_events` table — Stripe retries on failure, and we don't want to double-apply.

## Production checklist

- [ ] Use a live `sk_live_...` key, not `sk_test_...`.
- [ ] Replace the SQLite file with Postgres or your DB of choice (the schema is in `src/db.js`; the queries map 1:1).
- [ ] Put the server behind HTTPS (Caddy, Nginx, Cloudflare, your hosting platform's TLS termination).
- [ ] Register the production webhook endpoint in Stripe Dashboard → Developers → Webhooks. Use the secret it generates.
- [ ] Update `CHECKOUT_SUCCESS_URL`, `CHECKOUT_CANCEL_URL`, `BILLING_PORTAL_RETURN_URL` to your real domain.
- [ ] In the extension, set the subscription server URL (options page) to your production base URL, and add the URL to `host_permissions` in `manifest.json`.

## What this server intentionally does NOT do

- **No password auth, no email verification.** The `client_ref` UUID is the only auth. Threat model: an attacker who steals a UUID can see the tier but cannot grant themselves premium (they'd have to pay through Stripe to mutate state). For tighter linkage to a user identity, add Google sign-in via `chrome.identity` and key the row on Google `sub` instead.
- **No retries on webhook handler failures.** Stripe will retry for us on a non-2xx response.
- **No analytics, no logging of PII.** The DB stores only Stripe IDs and tier — never card numbers, names, or emails.
